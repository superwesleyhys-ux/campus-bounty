# Apply 与消息体验修复

之前没有完成用户可以直接使用的入口：本人发布的悬赏不显示 Apply，却未解释角色限制；另一个学生身份不可见；聊天入口隐藏，且需要手动刷新。技能数量和旧测试通过都没有覆盖这个实际问题。

## 现在可操作的流程

- 本机预览可明确切换 Alex、Sam、Professor 三个固定示例身份，保留当前页面。当前身份持续可见。
- 符合资格的其他学生在悬赏顶部看到 Apply to this bounty，点击定位申请表。发布者看到不能申请自己悬赏的解释及审阅入口。
- 提交申请成功后进入该申请的准确聊天。顶部 Messages 汇总本人有权查看的申请、协议与订单对话，发布者也可找到申请沟通。
- 可见页面约每三秒检查新消息；隐藏/离线暂停、失败退避。收到消息不清空草稿、不抢输入焦点；正在读旧消息时保留位置并提供新消息跳转。

## 实际验收

两个全新浏览器窗口均通过页面的示例身份按钮登录，没有注入会话。Alex 用界面发布专用合成悬赏，Sam 点击 Apply 并提交一次；两人从 Messages 打开同一申请并双向发信。收件方不刷新，实际到达分别 3.328 秒与 2.323 秒。收件箱初次出现耗时 302 毫秒，与首次加载重合，不能当成轮询延迟基准。

后续检查实际保留草稿/焦点、搜索结果/选中上下文、旧消息阅读位置；延迟发送确认与加载旧消息重叠后没有残留滚动锚点。撤回合成申请后发布者聊天自动变为只读且历史保留。390 像素视口无横向溢出；切换身份后旧私密内容隐藏。

根代理另在用户原页面切到 Sam，点击 Apply 后确认申请表定位和输入焦点；没有替用户提交申请、发送消息或修改原 doing pre 悬赏。

类型检查、6 项预览入口保护、3 项消息收件箱权限/分页及 10 项既有申请会话检查通过；后续 9 项是子集复跑，不能相加。早期浏览器检查有三个测试脚本定位/时序失败，原始记录保留，最终窄范围继续检查通过。本轮没有重新运行生产构建或全站套件。

独立 Astra High 审查通过，未发现可操作的返修项；16 个冻结文件哈希全部一致。实现报告与完整增量差异在本机 .superpowers/sdd/apply-chat-fix-plan/task-1-report.md 和 .superpowers/sdd/apply-chat-fix/full-context.diff。可读证据在 docs/evidence/apply-chat-fix/。

## 边界

这是本地示例账号与近实时轮询，未声称 WebSocket 推送、在线状态、已读回执或万人并发。申请/协议/订单之外的任意私信未增加。真实学校邮箱发信、真实支付和生产上线仍未完成。大量消息超过单次有界追赶时会要求手动刷新，不静默丢历史。

预览未重启，数据库未重建，既有权限和迁移未更改；整体开发目标保持暂停。本次只修复用户指出的入口和消息体验。源码同步目标为原有私有 GitHub 仓库 superwesleyhys-ux/campus-bounty；远端同步回执单独保存在本地 docs/evidence/apply-chat-fix/private-github-sync.json。

# 首次进入 Demo 的修复

用户实际从未登录页面打开 Marketplace，输入真实大学邮箱后被挡住。旧预览只接受合成测试邮箱，验证码被送到用户无法通过界面访问的本地文件。此前工程与技能试用通过预先登录的测试身份进入，未验证用户第一次进入的路径。这是交付遗漏。

## 范围与状态

本次仅修复当前本机 PostgreSQL 演示入口。全站开发目标保持暂停；并不将未完成的真实邮件、付款或部署计为完成。

真实邮件配置预检本次返回 `missing_configuration`：缺少 SMTP host、user、password、from；没有发送邮件，也没有真实收件或学校身份验证证据。现有预览使用合成邮件接收器。演示身份不能作为真实大学邮箱认证。

已实现：明确的学生/发布者示例身份入口，在浏览器正常建立演示会话，保留目标页面与退出功能。仅可丢弃、绑定本机的测试实例允许；生产及一般开发环境不得启用。普通邮箱认证逻辑保留。

## 实际验证

Astra High 完成实现。13 项配置、固定角色、会话与原认证接口定向检查通过，类型检查通过。1440×1000 与 390×844 的浏览器检查都从 0 cookie 开始，通过界面进入学生身份，显示实际 Marketplace，浏览与退出，再以发布者身份进入原物品详情。另有会话轮换、旧会话失效、非法输入及跨来源拒绝的定向检查。没有预先写入登录记录。

root 同时在用户原来的内置浏览器操作：首次新版点击仍出现 500，修复了认证数据库角色不具备目录表加锁权限的问题，没有扩大权限。随后重新加载并点击学生入口成功，显示 Alex / Sample account / Marketplace；页面留在可使用的学生演示状态。失败没有被抹去或计为通过。

证据目录为 `docs/evidence/first-entry-fix/`：`focused-tests.log`、`typecheck.log`、`browser-results.json`、四张桌面/手机截图、`controller-status.json`。独立 Astra High 审查：规格、质量与安全均通过，没有待修问题；核对全部 9 个改动输出与快照，未重复运行已通过测试。审查报告保留在 `.superpowers/sdd/first-entry-fix-plan/task-1-review.md`。

## 交付边界

- 真实邮箱发送与收件尚未接通，没有向用户真实邮箱发送验证码。
- 现有共享合成账号仅用于这台机器上的演示，不是个人正式账户。演示数据包含前几轮测试内容。
- 预览未重启，数据库未重建，迁移与权限未更改。
- 当前完整目标仍暂停，没有因修好入口就宣称全站可上线。
- GitHub 的 GraphQL 读取超时，随后 20 秒上限的 REST 读取也超时；本次尚未对远端执行写入。之前的私有上传不等于这次修复已同步。

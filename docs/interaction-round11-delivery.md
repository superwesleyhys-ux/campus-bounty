# 第十一轮：完整历史分页

本轮让 Workspace 的申请、协议、订单、本人悬赏、本人商品，以及 Saved 收藏可以持续翻页，解决旧入口只显示最近100条的问题。本轮已完成有边界的本地验收，最终限定复审通过。完整应用目标仍在进行；本轮不代表真实邮箱、支付或生产上线已完成。

## 用户可见变化

六类列表采用每页20条的稳定游标，显示本页实际数量、是否还有后续记录，提供下一页与返回最新记录。浏览器后退、重载、详情返回保留原列表位置；切换栏目清掉不适用的游标。Workspace 的 Refresh this page 保留当前页。读取失败提供重试，空旧页提供返回入口，切换身份清除前一账号记录。

查询保留当前权限检查。校园资格失效后，原本允许访问的申请、协议和订单历史仍可读，目录标题受保护；自己的目录与收藏仍要求当前校园资格。游标绑定当前账号和记录类型，不作为授权凭证。

## 执行决定与边界

1. 沿用权威特性分支的未提交源码，以逐文件快照审查增量，避免遗失此前工作；代价是额外维护快照证据。
2. 确认旧页面服务已停止、原数据库存在后，只恢复页面服务。旧库未重建/删除/迁移；邮件与库存到期后台进程未在本次一并恢复。
3. 六类历史统一采用稳定游标，公共目录旧查询保持原行为；代价是新增统一历史接口及类型。
4. 允许现有迁移仅初始化新建的独立测试库，测试后清理自己的临时库；不会升级或更改既有预览数据库。
5. 冻结源码的最终审查与只读dogfood并行，发现问题合并后再修复、定向复审；任何后续改动不能沿用旧源码的通过声明。
6. 手机收藏底部翻页这一轻微体验问题并入已经需要的最终修复，避免读完整页后必须反复滚回顶部；代价是少量界面改动和定向手机验证。
7. 沿用用户已授权的私有上传方式，保留原工作区和原始证据，用经过检查的独立导出同步；代价是单独核对导出文件与远端提交。
8. 以当前源码哈希和已完成的定向检查验收本轮，不重复执行无变化的广泛套件或受限诊断；不宣称本轮执行了完整套件或生产构建。
